# Spec Delta

## Purpose

Gives an imported recipe a picture when the source did not supply one, by generating it
from the recipe's own content, attaching it in Mealie, and marking the recipe so a
generated picture is never mistaken for a photo of the actual dish.

## ADDED Requirements

### Requirement: Picture only for recipes that have none

The service SHALL attach a generated picture only to a recipe that carries no image in
Mealie after the import has written it. An image that Mealie obtained from the source
SHALL NOT be replaced or deleted.

#### Scenario: Imported recipe has no image

- **WHEN** an import finishes and Mealie reports no image for the created recipe
- **THEN** the service generates a picture and attaches it to that recipe

#### Scenario: Mealie already scraped an image

- **WHEN** an import finishes and Mealie reports an existing image for the created recipe
- **THEN** no picture is generated, no image call is made, and the existing image stays
  untouched

#### Scenario: Source already known and recipe unchanged

- **WHEN** the same source is shared again and the service answers with the link to the
  recipe it imported earlier
- **THEN** no picture is generated for that repeated request, whether or not the recipe
  has an image

### Requirement: Picture depicts the recipe

The generated picture SHALL depict the finished dish described by the recipe that was
just imported, derived from that recipe's name and ingredients. The request SHALL ask for
a picture without text, captions, logos or watermarks, and SHALL NOT claim the picture is
a photograph of the specific source. A mark that the image provider itself stamps onto
every picture it returns is outside the service's control and SHALL NOT be treated as a
failure of the stage.

#### Scenario: Picture is derived from the recipe content

- **WHEN** a picture is generated for a recipe
- **THEN** the request to the image provider describes that recipe's dish, using its name
  and its ingredients, and no other recipe's content

#### Scenario: Provider stamps its own mark on the picture

- **WHEN** the configured provider returns every picture with its own watermark
- **THEN** the picture is attached and tagged as generated like any other, and nothing in
  the import fails or warns because of the mark

#### Scenario: Recipe content is too long for one request

- **WHEN** the recipe has more ingredients or steps than the stage sends
- **THEN** the request is shortened to a bounded size and the picture is still generated,
  rather than the request being sent unbounded or the stage giving up

### Requirement: Generated pictures are marked in Mealie

A recipe whose picture was generated by this service SHALL carry a tag in Mealie that
identifies the picture as generated, in addition to the `auto-import` tag every imported
recipe carries. A recipe that kept its scraped image or ended up with no picture SHALL
NOT carry that tag.

#### Scenario: Picture was generated and attached

- **WHEN** a generated picture has been attached to a recipe
- **THEN** the recipe carries both the `auto-import` tag and the generated-picture tag

#### Scenario: No picture was generated

- **WHEN** an import completes without a generated picture, for any reason
- **THEN** the recipe carries the `auto-import` tag only

### Requirement: The picture stage never fails an import

The picture stage SHALL NOT turn a successful import into a failed one. Every failure of
the stage - provider unreachable, provider error, unusable or empty answer, unreadable
image data, rejected upload - SHALL be logged and SHALL leave the import successful, the
stored entry `done`, and the recipe in Mealie intact without a picture.

#### Scenario: Image provider is unreachable or returns an error

- **WHEN** the image provider cannot be reached or answers with an error status
- **THEN** the import is still reported as successful with a link to the recipe, the
  recipe has no generated picture, and the reason is logged

#### Scenario: Mealie rejects the image upload

- **WHEN** the picture was generated but Mealie rejects the upload
- **THEN** the import is still reported as successful with a link to the recipe, the
  recipe keeps no picture and no generated-picture tag, and the reason is logged

#### Scenario: Provider answers with something that is not a usable image

- **WHEN** the provider answers with an empty body, a body in an unexpected shape, or
  bytes that are not a JPEG, PNG or WebP image
- **THEN** nothing is uploaded to Mealie, the import is still reported as successful, and
  the reason is logged

#### Scenario: The user-facing feedback does not change

- **WHEN** an import completes, with or without a generated picture
- **THEN** the push notification carries the same title, recipe name and recipe link as
  an import without this stage, and says nothing about the picture

### Requirement: The picture stage is configurable

The stage SHALL be controlled by configuration: an on/off switch that is on by default,
the choice of image provider, the name of the image model, and optional overrides for the
image provider's base URL and API key. The overrides SHALL default per provider: to the
values already configured for the text model when the image provider is the same kind of
OpenAI-compatible provider, and to that provider's own address with no key otherwise. The
service SHALL NOT send the text model's API key to a provider other than the text model's
own. No new mandatory configuration value SHALL be introduced, so an existing deployment
starts unchanged apart from the new stage.

#### Scenario: Stage switched off

- **WHEN** the switch is off and an import finishes for a recipe without an image
- **THEN** no image call is made, no picture is attached, no generated-picture tag is set,
  and the import completes as before

#### Scenario: Deployment upgrades without touching its configuration

- **WHEN** the service starts with a configuration that names none of the new values
- **THEN** the service starts successfully, the stage is on, and it uses the already
  configured text-model base URL and API key with the default image model

#### Scenario: Separate image provider configured

- **WHEN** an image base URL and image API key are configured
- **THEN** image generation uses those values while recipe extraction and naming keep
  using the text-model configuration

#### Scenario: Default provider needs no key

- **WHEN** the service runs with the default image provider and no image API key
- **THEN** pictures are generated without any credential, and the text model's API key is
  not sent to that provider

#### Scenario: Provider switched to an OpenAI-compatible one

- **WHEN** the image provider is configured as the OpenAI-compatible kind
- **THEN** the stage calls that provider's image endpoint with a JSON request and reads
  the picture out of its JSON answer, and every other behavior of the stage is unchanged

### Requirement: At most one image call per import

The stage SHALL make at most one image generation call per import, with no retry on an
unusable answer. An import that is skipped as a duplicate, that fails before the recipe
exists in Mealie, or whose recipe already has an image SHALL make no image call at all.

#### Scenario: Generation answer is unusable

- **WHEN** the single image generation call returns an unusable answer
- **THEN** the stage gives up without a second call and the import completes without a
  picture

#### Scenario: Import fails before the recipe exists

- **WHEN** extraction fails or Mealie rejects the recipe
- **THEN** no image call is made
